Local-only reference material. Nothing in this directory is committed except this file.

Fetch and convert the XISF specification in one step:

    ./tools/fetch-xisf-spec.sh

It downloads the compiled HTML, writes `xisf-1.0-spec.md` beside it, records the compiler
stamp in `xisf-1.0-spec.stamp`, and compares that stamp against the line below.
`tools/xisf-spec-to-md.py` does the conversion alone if the HTML is already local.

## Which build the citations were checked against

Verified against: Generated by the PixInsight Documentation Compiler script version 1.7.4 on 2026-09-16 15:11:42 UTC

That line is read by `tools/fetch-xisf-spec.sh`, which prints a warning when the fetched
document does not match it. Keep the two in step: when a fetch reports a mismatch, re-check the
citations and then update the line in the same change.

The check exists because the document has moved under a fixed URL before. Revision 1 (version
1.01, September 2026) replaced the April 2017 text at the same path, with the same filename,
and renumbered three things this repository cites — white space from §8.3.4 to §8.3.5, the CFA
pattern table from 15 to 18, and every equation after §8.5.4, downward, when the colour-space
transformations moved to the new normative Annex B. Nothing about the filename can express
that: the *format* version is still 1.0 and the *document* version is what changes, so the
compiler stamp is the only marker either document carries.

## Sources

The compiled HTML is the authority, and the reason is mechanical rather than a judgement about
trust: section, table and equation numbers are assigned by the documentation compiler at build
time, so the PIDoc source cannot tell you that a subsection is §8.3.5. A repository that cites
by number has to read the rendered document.

- Specification (compiled): <https://pixinsight.com/doc/docs/XISF-1.0-spec/XISF-1.0-spec.html>
- Specification (PIDoc source): <https://gitlab.com/pixinsight/XISF-specification>
- XML Schema for XISF headers: <http://pixinsight.com/xisf/xisf-1.0.xsd>
- FITS Standard 4.0: <https://fits.gsfc.nasa.gov/fits_standard.html>

§4 of the specification gives the compiled document's URL as `XISF-1.0.1-spec.html`. That path
returns 404; the unversioned one above is what serves the revision, and is what the fetch
script uses.

The PIDoc source repository carries both document versions and is useful for settling what
changed between them. It also carries two C++ listings the specification embeds. **The
reference implementation at `gitlab.com/pixinsight/PCL` is a different matter and is not to be
consulted**: this crate is written from the specifications alone, which is what keeps it
permissively licensable. §4 now advertises PCL directly beside the specification repository,
which makes it easier to open by accident than it used to be. `CONTRIBUTING.md` states the rule
that covers the embedded listings too — a specification that ships sample code is still
someone's copyrighted code.

## What the conversion loses

`tools/xisf-spec-to-md.py` is ours; its output is a format-shifted copy of Pleiades
Astrophoto's documentation and stays local. Two limitations are worth knowing before reading a
converted passage:

- **Equations are placeholders.** The document carries no MathML — every equation is an `<img>`
  with an empty `alt` — so a formula converts to `![eqn_0143.svg]()` and nothing else. Annex A
  and Annex B are largely unreadable in Markdown for this reason, and Annex B is normative.
  Read those two in the HTML.
- **Internal links dangle.** Cross-references survive as `[text](#anchor)`, but the headings
  carry no anchors, so following one in the Markdown goes nowhere.
